# TOYA One（TOYA社内用）

株式会社TOYAの社内アプリです。
入口: https://dkr77c498p-sketch.github.io/toya-one/

## 2026-09-15 建物用途の選択肢

- 建物用途を「住宅・事務所・店舗・工場・倉庫・その他」に整理しました。「用途未確認」は選択肢から外しています。
- 木造以外の店舗・工場・倉庫のコンクリート参考量は既存の「その他」共通係数を使い、画面と保存する根拠にその旨を表示します。木造は従来の用途共通係数を使います。選んだ用途は個別に保存します。
- 旧「用途未確認」の見積は再表示時に用途の選択を促し、住宅の係数へ置き換えません。保存済みの明細も、再作成するまで維持します。

## 2026-09-15 見積の工事種類を手入力

- 「工事の種類」から「その他（手入力）」を選ぶと、自由に工事名を入力し、品名・数量・単位・単価から見積を作れます。手入力には解体工事の標準数量・単価・経費率を当てはめません。
- 未入力の数量・単価は未確定として扱います。入力途中の工事種類と、適用済みの計算条件を分けて保存するため、種類の選択を変えただけでは既存の明細を置き換えません。
- `tests/estimate-manual-kind.cjs` は手入力、明細追加、保存・再表示、税込合計、印刷時の文字処理、再作成キャンセルを確認します。`tests/estimate-auto-ui.cjs` では既存の自動積算も確認します（Node.js と jsdom が必要）。
- `tests/estimate-manual-kind-database.sql` は一時的な会社・管理者で、実際の保存処理と計算結果を確認し、すべてロールバックします。データベースの定義変更はありません。

## 2026-09-15 社員一覧の修正

- `private.toya_employee_admin` の一覧取得で、社員レコード変数 `e` とテーブル別名が衝突していました。一覧のテーブル別名だけを `el` に変更しています。
- 管理者・所属会社・契約・端末の確認、関数の実行権限、社員作成とパスワード再設定の処理は維持しています。保存済みの業務データを更新する変更はありません。
- ホーム画面上部とページタイトルに「TOYA社内用」を表示します。

`tests/company-access-database.sql` は一時的な会社・ユーザーで、空の一覧、登録済み社員の一覧、会社間の分離、管理者以外の拒否、社員作成・再設定を確認します。すべてのテストデータはトランザクションをロールバックして破棄します。

SQLの名前衝突については [PostgreSQL公式ドキュメント](https://www.postgresql.org/docs/17/plpgsql-implementation.html#PLPGSQL-VAR-SUBST) を参照してください。
