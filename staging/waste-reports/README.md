# TOYA 一般廃棄物・自社運搬実績（本番未反映）

ユーザーは2026-09-24に一般廃棄物収集運搬業の許可保有を確認し、TOYA自身の実績報告書を指定。
`report-profile.json` はこの確認を記録する検証用設定。許可番号は未確認のためnull。実際の許可証に記載された番号・住所・名称との照合が必要。
このフォルダーのコードは本番から読み込まれない。日報・認証・会社データ・データベース・index.htmlは変更していない。
前回の台帳の画像見本はあるが、旧試作のソースは作業環境/既存ブランチで確認できなかったため、この自社運搬集計モジュールを新しく保存する。

## 公式報告と社内集計
一般廃棄物処理業（収集運搬）実績報告書は鹿児島市分の月次報告。実績の有無にかかわらず翌月10日まで。
車両番号ごとに、可燃物（北部/南部）、不燃物（横井）、粗大ごみ（処理棟）、資源物を分ける。
ユーザーの入力用表示名は「横井処分」「北部清掃処分」および「可燃物・不燃物・粗大ごみ」。
粗大ごみは北部の可燃物欄へ流さず、処理棟搬入を別に確認する。これは受入可否や産廃/一般を自動判定する機能ではない。
「契約事業所報告書」も必要。契約先名、所在地、電話番号、店舗数、新規/廃止、月間収集量、週当たり収集回数などは別途入力が必要。
年度一覧は4月～翌3月の社内累計。一般廃棄物の月次提出を年一回で代用するものではない。

## この検証で実装したもの
- 自社companyId、一般廃棄物、自社運搬、鹿児島市の収集区域に限定した月次集計。
- 登録車両番号・搬入先・種類ごとの数量と4月～翌3月の12か月一覧。
- kg/tは整数グラムで換算。実測正味kgがあればその値だけを使用。m³だけでは重量を推測しない。
- 同じIDの同一取得は一回。異なる内容の同じID、同一計量票の別行は保留して要照合表示。
- 車両番号/重量/搬入区分/許可番号未設定、未照合、0件未確認を入力上の準備完了にしない。
- 中間的な転記用CSV。自動提出・提出済み表示はしない。CSV数式対策を行う。
- ローカルNodeの架空データ試験25件が合格。ネットワーク/実アカウントは使っていない。
- 架空の3記録（可燃250kg、不燃0.12t、粗大60kg）の集計は430kg。画面見本も架空。

## 日報連携の安全条件
1. 区分・種類・処分先・搬入日・登録車両番号・数量/単位・確定重量・計量票番号/写真・運搬業者・収集区域を記録する。
2. 一般廃棄物を既存の産廃isWaste/waste_entriesに入れない。旧データの廃棄物区分は推測しない。
3. 日報保存はreport_dataへオブジェクトを保管するが、フォーム取得は列挙式。変更時は編集/複製/復元/旧端末の再保存で新項目が欠落しないか検証する。
4. 既存cloudReportsCacheは500件取得上限がある。年次集計には会社・期間条件でページングする。読み込み失敗を0件としない。
5. 日報本体・移動先・補助表で同じ搬入を二重計上しない。会社切替時は元会社情報を消去し、全社集計/設定は管理者のみ。
6. 日報の原価に処分費を入れる場合も同一費用を二重に加算しない。
7. 産廃の紙マニフェスト年次報告は別枠。TOYA交付・元請交付・電子・一般廃棄物を混ぜない。交付日基準/種類/運搬先/処分先等を別検証する。
8. 作業ブランチの検証後も、許可情報、日報の実保存、全件取得、公式出力を確認するまで本番へ統合しない。
