# 自動積算表・見積書／現場・請求・完工（v5.7.4）

管理者ホームの「新しい見積書を作る」から、未登録の新しい工事の積算・見積を作成できます。工事名・工事住所・見積先を入力して保存でき、過去や着工中の現場を選ぶ必要はありません。日報から集計する全現場の実績も同じカードの下部へ自動表示します。登録管理にも入口があります。社員には積算・見積・利益・請求・完工の管理画面を表示せず、費用データは管理者権限で保護します。

## 会社の見積書から取り込んだ数量表

ホームの「自動積算表・見積書」の先頭に、取り込み済み見積書を表示します。見積書名を選ぶと、仮設・解体・運搬処分などの工事項目ごとに、原本の数量・単位・階や部屋・備考を確認できます。作成ボタンを押す必要はありません。

- 数量の空欄、金額の空欄、「別途」、控除、原本のページを残します。㎡・㎥・t・台・式は相互換算せず、床仕上げと下地など同じ数量の別工程も分けて保存します。
- 原本の単価・金額・条件は参考欄で確認できます。原本の矛盾や確認すべき単位には注意事項を表示し、金額の空欄を数量×単価で勝手に埋めません。
- 「この数量で見積を作る」は、新しい工事が初期選択です。「この数量で新しい見積を作る」で数量入力済みの見積を開き、工事名・住所を入力できます。登録済み現場を選んで引き継ぐこともできます。工事条件と原価単価を確認して保存します。元見積の売価を原価単価には転記せず、諸経費・値引きも今回の積算で設定します。
- 数量表の工事名と登録現場の対応が不明な場合、現場を自動作成・紐付けしません。完工済みの登録現場も、数量の引き継ぎ先として選べます。
- 数量表は見積時の予定数量です。日報の施工実績・原価・請負売上へ二重加算しません。原本からの数量表は閲覧用として残り、コピー先を編集しても変わりません。
- 管理者だけが同じ会社の数量表を閲覧できます。「この数量表を印刷・PDF」で社内用の数量積算表を出力できます。

## 日報から自動で積み上がる積算表

- TOYA Oneに登録した施工予定・施工中・完工済み・過去の現場を一覧に表示します。請負金額、常用に行く分を含む売上、入力済み原価、概算利益を確認できます。
- 日報、登録単価、保存済みの費用調整額を、ホームの現場別原価と同じ計算で全期間集計します。保存済みの調整額（0円も含む）を優先し、燃料は使用料から差し引かず別に1回だけ加えます。
- 「内訳」または現場選択で、費目別・日別の積算と要確認事項を表示します。「請負金額・原価を確認」から既存の確認・調整画面へ移動できます。
- 日報・費用の記録がない現場は「記録なし」と表示し、利益を計算しません。請負金額が未登録の場合も利益を表示しません。合計は、日報・費用と請負金額の両方がある同じ現場群で算出し、対象外の現場数を併記します。
- ホームを開いたとき、画面に戻ったとき、ホーム表示中は約1分ごとに再集計します。「日報から再集計」でも更新できます。全データを読み込めなかった場合は古い合計を消してエラーを表示します。
- 表示のために日報・費用調整・請負金額へ書き込みません。未記録の費用は含まない概算で、完工設定だけでは費用の確認済み・確定にはなりません。
- 一覧または選択した現場の積算表を、社内用として印刷・PDF保存できます。

## 実績を参考に見積書を作る

実績のある現場では「この実績を見積の参考に使う」で、集計済みの費目別金額を見積用の下書きに取り込めます。原価をもう一度入力する必要はありません。取り込み後は独立した見積なので、日報を変更しても見積の金額は変わりません。要確認費用が残る場合は未入力行を残し、確認前に見積額を確定しません。施工条件・見積先・諸経費・利益を確認して保存してください。

新しい工事の予定数量や日数は、実績だけでは決まりません。提出用の見積を新しく作る場合は、通常は閉じている「見積書の作成・保存済み見積」を開きます。

## 新しい見積の作成手順

1. 「新しい見積書を作る」を押し、工事名・工事住所・見積先を入力します。見積件名は空欄なら工事名から補います。受注前の見積として保存し、日報用の現場や売上を作成しません。
2. 内装解体・重機解体・運搬処分などの工事項目を追加します。会社の数量表や保存済み積算表を複製して、新しい工事の見積に使うこともできます。
3. 各工事項目へ人工・重機・車両・アタッチメント・小型機械・燃料・材料・処分・回送・外注などを積み上げます。数量 × 日数・時間・回数 × 原価単価で自動計算します。人工3人 × 5日、工具2台 × 4時間、材料数量 × 1回など、単価の単位に合わせて入力してください。
4. 登録済みの人工・車両・重機・アタッチメント・工具・処分・回送の単価を取り込めます。燃料は別の内訳に加算します。取り込んだ単価は積算表に保存し、その後の単価マスタ変更では書き換えません。
5. 諸経費率、利益上乗せ率を入力します。不要な場合は0。直接工事費に諸経費を加え、その合計原価に利益を上乗せします。「見積額を調整する」では提出額を1円単位で指定でき、見込利益・利益率も再計算します。利益上乗せ率と利益率は分母が異なります。
6. 「積算表を保存」。未入力の内訳がある途中段階でも保存できます。空欄を0円とは扱わず、全て揃った表から見積書を作ります。
7. 「この積算から見積書を作る」で、工事項目ごとの金額を見積書の下書きへ引き継ぎます。諸経費と見積金額は原価比率で配分し、整数円の配分合計を一致させます。全工事項目の原価が0円の場合は等分します。
8. 宛先・発行者・期限・条件を確認して下書き保存、プレビュー、確定・採番、印刷・PDF保存へ進みます。

既存現場の追加工事などは、下部の現場を選び「この登録現場で見積を作る」から作成します。新しい工事の見積と既存現場の見積は、どちらも保存済み一覧で開けます。新しい工事の見積書も下書き保存・確定採番・印刷まで進められます。請求書・出来高請求書には受注した現場の登録が必要です。

「積算表を印刷」は原価・社内メモ入りの社内用です。提出用の「見積書」は工事項目と提出金額を載せ、内部の人工・費用内訳・利益・社内メモを載せません。

完工済み現場などの保存済み積算表は、「この積算表を複製して使う」で別の現場へコピーできます。元の積算表、日報、実績原価、請負金額は変更しません。複製後に必要な工事・数量・単価を追加・調整して保存してください。

見積書には作成時の積算内容を保存します。その後に積算表を直しても過去の見積書は変わりません。見積額の変更は積算表で行い、新しい見積書を作成します。同時に別端末から更新されていた場合は、上書きせず再読込を求めます。

## 請求・完工


- **完工設定**：完工日を保存すると、通常の日報の現場候補から外れます。過去の日報・費用・書類は残ります。「工事中に戻す」で再開できます。完工は費用の確定や入金済みを意味しません。
- **請求書**：請負金額がある場合は未請求残額を明細に入れて開始します。確定した見積から明細を引き継ぐこともできます。
- **出来高請求書**：累計出来高を金額または率で入力し、前回までの確定済み請求額を引いた今回分を計算します。請負金額を超える請求は保存・確定時に確認します。

最初に「発行者情報の設定を開く」または「発行者・振込先の設定」で自社情報を登録してください。登録番号は、登録している場合に入力します。宛先・件名・取引日・支払期限を確認し、**下書き保存 → プレビュー → 内容を確定・採番 → 印刷・PDF保存**と進みます。

書類番号は確定時に自動で付きます。確定済み書類の内容は固定され、取消理由を残して取り消せます。後続の請求書がある場合は新しいものから取り消します。取消済み書類も履歴に残ります。相手先への自動送信はありません。

請求書は既存の請負売上へ二重加算しません。確定済み見積は、金額を確認して「この見積額を請負金額に設定」を押したときに限り、請負金額・利益計算へ反映します。未請求額は入金残高とは別の指標です。

数量は小数3桁、単価は小数2桁まで。明細金額の1円未満は切捨て、消費税は書類全体の税別小計から1回だけ切り捨てます。1書類内の税率は統一し、10%・8%（軽減税率）・非課税／対象外を選べます。税率別の記載事項と端数処理は、[国税庁の記載事項](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6625.htm)・[端数処理](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6371.htm)を参照しています。

## 検証

`tests/new-job-estimates-database.sql` で、現場未登録の見積の途中保存・金額計算・作成時点の内容保持・確定採番・取消・管理者限定の権限を検証します。検証は必ずトランザクション内で実行してロールバックします。

`node tests/estimate-quantities.cjs` と `tests/estimate-quantities-ui.cjs`（jsdom）で、数量・単位・空欄・原本の控除の保持、原価との区別、現場への引き継ぎ、管理者限定表示、読み込み失敗・ログアウト時の消去を検証します。`tests/estimate-quantities-database.sql` は検証用の管理者・社員IDを指定し、必ずトランザクション内で実行してロールバックします。顧客別の原本データやPDFは公開リポジトリへ含めません。

`node tests/site-auto-ledger.cjs` と `tests/site-auto-ledger-ui.cjs`（jsdom）で全現場の自動集計・未登録・日報追加・権限・読み込み失敗・実績取込みを検証します。`node tests/estimate-plan.cjs` と `node tests/project-documents.cjs` で積算・出来高・印刷内容を検証します。`tests/project-business-ui.cjs` は jsdom を用いた実際のフォーム操作の検証です。`tests/estimate-plan-database.sql` と `tests/project-documents-database.sql` はトランザクション内で番号・同時更新・取消・権限・完工を検証するためのSQLで、検証後は必ずロールバックします。既存の日報や請負金額の書き換えは行いません。
